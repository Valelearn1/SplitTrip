# SplitTrip v3.5 — App installabile e offline (design)

Data: 2026-10-19 · Stato: approvato in chat dall'autrice (sezioni 1–4) · ✅ implementato il 2026-10-19 · Consegna del capstone: domenica 25 ottobre, ore 21 · Presentazione: 28 ottobre

## 1. Perché

| Problema | Effetto per chi usa l'app |
|---|---|
| All'estero senza roaming, o in metro, l'app non mostra niente | i conti del viaggio non si possono consultare proprio quando servono |
| Il server gratuito si addormenta: la prima apertura aspetta fino a un minuto | si guarda una pagina vuota invece degli ultimi dati visti |
| L'app vive solo in una scheda del browser | niente icona sul telefono, apertura con la barra del browser |

**Successo:** alla presentazione si installa SplitTrip sul telefono, si attiva la modalità aereo e si consultano Home, viaggio, spese, saldi, liste, chat e foto già viste; le modifiche sono chiaramente disattivate; uscendo dall'account sul telefono non resta niente.

**Vincoli:** solo frontend (il backend non cambia); nessuna modifica salvata senza rete (le spese offline richiedono id generati dal client e gestione dei conflitti, ROADMAP §2 voce 2); CSP invariata nella sostanza.

## 2. Decisioni

| ID | Decisione | Alternative scartate |
|---|---|---|
| D-63 | **PWA con consultazione offline in sola lettura**: `vite-plugin-pwa` (Workbox, `generateSW`, `registerType: 'prompt'`) per app installabile, guscio in cache e foto già viste; cache di TanStack Query salvata in IndexedDB (`@tanstack/react-query-persist-client`, `@tanstack/query-async-storage-persister`, `idb-keyval`) per i dati; senza rete nessuna scrittura (né in coda né rimandata); tutto cancellato all'uscita dall'account | service worker scritto a mano + `localStorage` (hash dei file a mano, 5 MB, lento); solo service worker che salva ogni `GET /api` (TanStack Query offline non chiede i dati, ora dei dati da ricavare dagli header, cache difficile da svuotare in modo mirato); modifiche in coda da inviare al ritorno della rete (duplicati di spese, conflitti) |

Scelte dell'autrice in chat: offline anche le **foto già viste**; installazione con un **bottone nel Profilo**; aggiornamento con l'**avviso «Aggiorna»**; approccio A.

Versioni: Vite 8.2.2 nel progetto; `vite-plugin-pwa` 2.0.0 dichiara compatibilità con Vite 3–8.

## 4. Aggiornamento

- Registrazione nel codice con `useRegisterSW` di `virtual:pwa-register/react` (`injectRegister: false`: nessuno script inline in pagina, l'hash CSP di `index.html` non cambia).
- `UpdateBanner`: quando c'è una versione nuova (`needRefresh`) una barra fissa in basso, sopra la tab bar, `role="status"`: «C'è una nuova versione di SplitTrip», bottoni **«Aggiorna»** (`updateServiceWorker(true)`: attiva e ricarica) e **«Dopo»** (nasconde fino al prossimo avvio).
- Controllo degli aggiornamenti anche ogni ora (`registration.update()`), perché l'app installata resta aperta a lungo.
- Service worker spento in sviluppo (`devOptions.enabled: false`): `npm run dev` resta com'è; le prove si fanno con `npm run build && npm run preview`.

## 5. Service worker (Workbox, `generateSW`)

| Cosa | Strategia | Limiti |
|---|---|---|
| Guscio dell'app: HTML, JS, CSS, SVG, PNG di `dist` | precache (`globPatterns: ['**/*.{js,css,html,svg,png,webmanifest}']`) | aggiornato a ogni build |
| Navigazione (ogni pagina dell'app) | `navigateFallback: '/index.html'`, con `navigateFallbackDenylist: [/^\/api\//]` | — |
| Font: CSS di `fonts.googleapis.com` | `StaleWhileRevalidate`, cache `splittrip-font-css` | 10 voci |
| Font: file di `fonts.gstatic.com` | `CacheFirst`, cache `splittrip-font`, solo risposte 0/200 | 30 voci, 365 giorni |
| Foto, miniature, scontrini: `GET <API>/trips/{id}/photos/{id}/(image\|thumbnail)` | `CacheFirst` (una foto caricata non cambia), cache `splittrip-foto`, solo risposte 200 | 150 voci, 30 giorni |
| Avatar: `GET <API>/users/{id}/avatar` | `StaleWhileRevalidate`, cache `splittrip-avatar`, solo 200 | 60 voci, 30 giorni |
| Tutto il resto di `/api` e il WebSocket `/ws` | **mai** in cache | — |

`<API>` è l'origine di `VITE_API_URL` (in produzione `https://splittrip-api.onrender.com`); le regole si costruiscono da quella variabile nella config di Vite, così valgono anche in locale. Le richieste delle immagini portano l'header `Authorization`: la Cache API le indicizza per URL, il dispositivo è di una persona sola e le cache si cancellano all'uscita (§8).

## 6. Dati offline

### Persistenza della cache di TanStack Query

| Voce | Scelta |
|---|---|
| Dove | IndexedDB tramite `idb-keyval` (database `keyval-store` di base, chiave `splittrip-cache`) |
| Come | `PersistQueryClientProvider` al posto di `QueryClientProvider` in `App.tsx`, con `createAsyncStoragePersister` e `throttleTime: 1000` |
| Durata | `maxAge` 7 giorni; `gcTime` di base delle query 7 giorni (altrimenti spariscono dalla memoria prima di essere salvate) |
| Marchio (`buster`) | `` `${CACHE_VERSION}:${userId}` ``: `CACHE_VERSION` è una costante (parte da `1`) da aumentare a mano quando cambia la forma dei dati dell'API; senza utente nessuna cache viene ripristinata |
| Cosa si salva (`shouldDehydrateQuery`) | solo query `success` con chiave che inizia per `home`, `trips`, `chat`, `notifications`, `me` |
| Cosa non si salva | `blob` (immagini: hanno la cache del service worker), `ai`, `join-preview`, ricerche di luoghi, query in errore o in attesa |

Funzione pura `shouldPersist(query)` in `features/pwa/persistence.ts`, testata da sola; la lista delle chiavi ammesse sta lì.

### Senza rete

| Situazione | Comportamento |
|---|---|
| Pagina già aperta | i dati salvati compaiono subito (le query in pausa offline mantengono i dati) |
| Pagina mai aperta | invece dello spinner infinito, `OfflineEmpty`: icona `cloud_off`, «Questa pagina non è ancora salvata sul telefono: aprila una volta con la rete». Lo mostra `Spinner` stesso quando la rete manca: le 12 pagine che fanno `isPending && <Spinner />` lo ottengono senza modifiche |
| Torna la rete | le query ripartono da sole (comportamento di TanStack Query) |

### Foto già viste

- `AuthImage` usa `networkMode: 'offlineFirst'` per la query `['blob', path]`: senza rete prova comunque la richiesta e il service worker risponde dalla cache.
- Foto mai vista e niente rete: segnaposto `image_not_supported` con «Serve la rete», stessa misura dell'immagine.
- **Mappa solo online**: le tessere di OpenStreetMap non si salvano (regole d'uso del servizio). Offline, al posto della mappa: «La mappa serve la rete»; la griglia delle foto funziona.

Spazio stimato: dati sotto 1 MB; foto al massimo circa 30 MB.

## 7. Modifiche e avvisi senza rete

**Regola:** senza rete si guarda ma non si cambia. Nessuna modifica resta in attesa.

| Livello | Cosa fa |
|---|---|
| Controlli disattivati | il `Button` condiviso con `type="submit"` o con la nuova prop `needsNetwork` è disattivato offline, con «Serve la rete per salvare» sotto (`aria-describedby`) |
| Rete di sicurezza | default delle mutation `networkMode: 'always'`: una modifica partita offline fallisce subito; `FormError` mostra «Connessione persa: la modifica potrebbe non essere stata salvata. Controlla prima di riprovare» e i campi restano compilati (*rivisto dopo la revisione finale*: se la rete cade dopo il salvataggio sul server il browser non lo sa, e «non è stata salvata» inviterebbe a creare un doppione) |

| Dove | Offline |
|---|---|
| FAB «Nuova spesa» (link) e «Carica foto», «Salda», «Chi offre?», «Indovina il totale» | disattivati, con il motivo come nome accessibile e `title` |
| Spunta delle voci, reazioni, eliminazione messaggi | il controllo resta visibile ma non agisce; un tocco mostra «Serve la rete» in un avviso breve (`role="status"`) |
| Campo della chat | disattivato, con «Sei offline: i messaggi tornano con la rete» |
| Accesso, registrazione, password dimenticata | il bottone resta attivo; all'invio «Serve la rete per entrare» invece dell'errore generico |
| Esci | sempre possibile (cancella i dati sul dispositivo, §8) |

Hook `useOnline()` in `features/pwa/useOnline.ts` sopra `onlineManager` (`useSyncExternalStore`): un solo punto da cui tutti leggono lo stato della rete.

### Barra offline: `OfflineBanner`

- In cima, come `WakingBanner`: icona `cloud_off` + «Sei offline · dati delle HH:MM · le modifiche tornano con la rete»; `role="status"`.
- **L'ora** è quella del dato **più vecchio tra le query attive** della pagina (`dataUpdatedAt` minimo tra quelle con dati); se non è di oggi: «dati del 18/10 alle 21:40». Funzione pura `dataAgeLabel(timestamps, now)`.
- Al ritorno della rete: «Di nuovo online» per 3 secondi, poi sparisce.
- Offline vince: `WakingBanner` non compare mentre `OfflineBanner` è visibile.
- Mai solo colore: icona + testo (D-24). Testo fuori dalle card: verificarlo sopra lo sfondo stagionale nei due temi.

## 8. Sicurezza e privacy

| Rischio | Difesa |
|---|---|
| Viaggi, spese e chat restano sul telefono | `clearDeviceData()` in `features/pwa/deviceData.ts`: `queryClient.clear()`, `persister.removeClient()` (chiave IndexedDB), `caches.delete` di `splittrip-foto` e `splittrip-avatar`. La chiama `logout` (anche quello automatico dopo un 401) |
| Un'altra persona entra sullo stesso telefono | il `buster` con l'id utente scarta la cache precedente prima di mostrarla |
| Il service worker salva ciò che non deve | in cache solo guscio, font e i tre indirizzi di immagini (§5); mai JSON di `/api`, mai `/ws` |
| Token scaduto, telefono offline | i dati già visti restano visibili fino all'uscita, come oggi il token in `localStorage`; consiglio nel README: «sul telefono di altri, esci sempre». Rischio accettato |
| Memoria piena | se il salvataggio fallisce l'app continua online senza copia offline (avviso in console, nessun errore a schermo) |
| CSP | invariata nella sostanza; si aggiungono `worker-src 'self'` e `manifest-src 'self'` per chiarezza |
| Backend | nessuna modifica; nessun dato nuovo lascia il dispositivo |

## 9. Render

- `sw.js`, `workbox-*.js` e `manifest.webmanifest` serviti come file veri: verificare che la regola `/* → /index.html` non li intercetti (Render serve prima i file esistenti; se non fosse così, una regola apposita prima del rewrite).
- Header `Cache-Control: no-cache` per `/sw.js` e `/manifest.webmanifest`; gli asset con hash restano in cache lunga.
- CSP aggiornata come al §8.

## 10. Test

**Automatici (Vitest), scritti prima del codice**

| Area | Casi |
|---|---|
| `shouldPersist` | `home`, `trips/...`, `chat/...`, `notifications`, `me` in successo → sì; `blob`, `ai`, `join-preview`, query in errore → no |
| `buster` | contiene `CACHE_VERSION` e l'id utente; utenti diversi → marchi diversi |
| `clearDeviceData` | svuota il client, rimuove la chiave IndexedDB, cancella le due cache; `logout` la chiama |
| `dataAgeLabel` | oggi → «dati delle HH:MM»; altro giorno → «dati del GG/MM alle HH:MM»; nessun dato → solo «Sei offline» |
| `OfflineBanner` | compare offline e sparisce online; usa il dato più vecchio delle query attive; «Di nuovo online» per 3 s; `WakingBanner` nascosto offline |
| Pagina mai aperta offline | `OfflineEmpty` al posto dello spinner |
| Modifiche offline | `Button` submit disattivato con il motivo; mutation partita offline → messaggio e campi intatti; campo chat disattivato; accesso → «Serve la rete per entrare» |
| `AuthImage` | offline senza copia → segnaposto «Serve la rete» |
| `InstallApp` | evento catturato → «Installa» chiama `prompt()`; iOS → due passi; standalone → installata; altro → testo del menu |
| `UpdateBanner` | `needRefresh` → barra; «Aggiorna» chiama `updateServiceWorker(true)`; «Dopo» la nasconde |
| Manifest | nome, `standalone`, `start_url`, icone 192/512/maskable presenti in `public/` |

**A mano** (in locale con `npm run preview` e sul sito pubblicato; sul telefono l'autrice):
- Chrome, pannello Application: manifest valido, service worker attivo, installabile.
- Rete «Offline» in DevTools: Home, viaggio, spese, saldi, liste, chat, foto già viste; mappa con il messaggio; bottoni di modifica disattivati.
- Dopo «Esci»: IndexedDB e cache `splittrip-*` vuote.
- Un deploy nuovo → barra «Aggiorna» → la versione cambia.
- Telefono: installazione (Android o iPhone), modalità aereo, consultazione.
