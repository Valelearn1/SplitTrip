# SplitTrip v3.6 Valute — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spese e rimborsi in un'altra valuta col cambio del giorno salvato, importo convertito usato nei conti, e i tre ritocchi sulle valute senza centesimi.

**Architecture:** Il backend tiene lo scontrino (`amount`, `currency`), il cambio (`fxRate`) e l'importo convertito (`amountBase`); i conti leggono solo `amountBase`. Il cambio suggerito arriva da Frankfurter (BCE) tramite un client nel backend con cache, come i luoghi. Il frontend aggiunge il menu della valuta, la riga del cambio e l'anteprima nei moduli di spesa e rimborso, e mostra «2.000 JPY ≈ 11,25 €» negli elenchi.

**Tech Stack:** Spring Boot 4.1 / Java 25, Flyway (V10 per i rimborsi), RestClient + MockRestServiceServer, React 19 + TypeScript, Vitest + Testing Library + MSW, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-v3.6-valute-design.md`

## Global Constraints

- TDD: il test si scrive prima e si vede fallire.
- Soldi: `BigDecimal` scala 2 HALF_UP, mai `double`. Cambio: scala 8 HALF_UP.
- Schema solo via Flyway; `ddl-auto=validate`. Mai toccare una migrazione già applicata. La V10 tocca solo `settlements`.
- Servizi esterni solo dal backend (D-46, D-51): al servizio dei cambi vanno solo due codici valuta e una data.
- Valute senza centesimi (D-70): `JPY, HUF, ISK, KRW`, stesso elenco in `BE/.../common/Currencies.java` e `FE/src/shared/utils/currencies.ts`.
- Tetti (D-70): 999.999,99 con centesimi; 99.999.999 senza; anche sull'importo convertito.

- Numeri: «2.000 JPY», «1.234,56 €» con il punto delle migliaia sempre, nel browser come nel server.

## Review Focus

1. **Cambio scritto a mano «0» o «0,000»**: la spesa non si salva e il messaggio lo dice; mai una divisione per zero né un importo convertito a 0. Test nel Task 2 (`fxRate` 0 → 400) e nel Task 5 (campo a mano).
2. **Spesa in yen che supera il tetto una volta convertita** (es. 99.999.999 JPY ≈ 562.000 €, va bene; ma 99.999.999 KRW con un cambio alto no): il server rifiuta con «Al massimo 999.999,99 (due decimali)» sul convertito. Test nel Task 2.
3. **Modifica di una spesa vecchia in euro**: il modulo manda `currency: "EUR"`, `fxRate: 1`; quote e importo identici a prima, nessuna riga «cambio». Test nel Task 5.
4. **Servizio dei cambi che risponde ma senza la valuta chiesta** (JSON senza `rates[to]`): 404 «cambio non disponibile», non un errore 500. Test nel Task 1.
5. **Il saldo con rimborsi in valuta**: un rimborso da 5.000 JPY (28,12 €) su un debito di 30 € lascia 1,88 € da pareggiare, mai un credito inverso per arrotondamento. Test nel Task 7.

```java
package com.splittrip.rates;

import org.springframework.web.client.RestClient;

import java.math.BigDecimal;
import java.math.RoundingMode;
import java.net.URI;
import java.time.LocalDate;
import java.util.Map;
import java.util.Optional;

/**
 * Frankfurter (dati BCE, D-69): tassi contro l'euro e rapporto calcolato da noi. Il cambio diretto del servizio ha
 * solo 3 cifre significative (1 JPY = 0.00564 EUR): su 100.000 yen sbaglia di mezzo euro.
 */
public class FrankfurterRatesClient implements RatesClient {

    record Response(LocalDate date, Map<String, BigDecimal> rates) {}

    private final RestClient rest;

    public FrankfurterRatesClient(RestClient.Builder builder) {
        this.rest = builder.defaultHeader("User-Agent", "SplitTrip (capstone)").build();
    }

    @Override
    public Optional<Quote> rate(LocalDate date, String from, String to) {
        URI uri = URI.create("https://api.frankfurter.dev/v1/" + date + "?base=EUR&symbols=" + from + "," + to);
        Response r = rest.get().uri(uri).retrieve().body(Response.class);
        if (r == null || r.rates() == null) return Optional.empty();
        BigDecimal fromRate = "EUR".equals(from) ? BigDecimal.ONE : r.rates().get(from);
        BigDecimal toRate = "EUR".equals(to) ? BigDecimal.ONE : r.rates().get(to);
        if (fromRate == null || toRate == null || fromRate.signum() == 0) return Optional.empty();
        return Optional.of(new Quote(toRate.divide(fromRate, 8, RoundingMode.HALF_UP), r.date()));
    }
}
```

```java
package com.splittrip.rates;

import com.splittrip.common.AppException;
import com.splittrip.common.FieldException;
import com.splittrip.common.NotFoundException;
import com.splittrip.rates.dto.RateResponse;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;

import java.math.BigDecimal;
import java.time.Clock;
import java.time.LocalDate;
import java.util.Collections;
import java.util.LinkedHashMap;
import java.util.Map;
import java.util.Optional;
import java.util.regex.Pattern;

/** Cambio del giorno (D-69): valida, mette in cache per (data, da, a); valuta fuori lista → 404, servizio giù → 503. */
@Service
public class RatesService {

    static final int CACHE_SIZE = 2000;
    private static final Pattern ISO = Pattern.compile("^[A-Z]{3}$");
    private static final Logger log = LoggerFactory.getLogger(RatesService.class);

    private final RatesClient client;
    private final Clock clock;
    private final Map<String, RateResponse> cache = Collections.synchronizedMap(new LinkedHashMap<>(64, 0.75f, true) {
        @Override protected boolean removeEldestEntry(Map.Entry<String, RateResponse> e) { return size() > CACHE_SIZE; }
    });

    public RatesService(RatesClient client, Clock clock) {
        this.client = client;
        this.clock = clock;
    }

    public RateResponse rate(LocalDate date, String from, String to) {
        if (from == null || !ISO.matcher(from).matches()) throw new FieldException("from", "Valuta in formato ISO a 3 lettere");
        if (to == null || !ISO.matcher(to).matches()) throw new FieldException("to", "Valuta in formato ISO a 3 lettere");
        if (date == null) throw new FieldException("date", "Scegli una data");
        if (date.isAfter(LocalDate.now(clock))) throw new FieldException("date", "Il cambio di una data futura non esiste ancora");
        if (from.equals(to)) return new RateResponse(BigDecimal.ONE, date);
        String key = date + "|" + from + "|" + to;
        RateResponse hit = cache.get(key);
        if (hit != null) return hit;
        Optional<RatesClient.Quote> quote;
        try {
            quote = client.rate(date, from, to);
        } catch (RuntimeException e) {
            log.warn("Cambi non disponibili: {}", e.getMessage());
            throw new AppException(HttpStatus.SERVICE_UNAVAILABLE, "Cambi non disponibili", "Servizio dei cambi non disponibile: scrivi il cambio a mano");
        }
        RateResponse r = quote.map(q -> new RateResponse(q.rate(), q.date()))
                .orElseThrow(() -> new NotFoundException("Cambio non disponibile per " + from + ": scrivilo a mano"));
        cache.put(key, r);
        return r;
    }
}
```

```java
public final class Currencies {
    public static final Set<String> NO_CENTS = Set.of("JPY", "HUF", "ISK", "KRW");

    private Currencies() {}

    public static int fractionDigits(String currency) {
        if (NO_CENTS.contains(currency)) return 0;
        try {

        } catch (IllegalArgumentException e) {

            return Currency.getInstance(currency).getDisplayName(java.util.Locale.ITALIAN).toLowerCase(java.util.Locale.ITALIAN);
        } catch (IllegalArgumentException e) {
            return currency;
        }
    }
```

```java
package com.splittrip.common;

import java.math.BigDecimal;
import java.math.RoundingMode;

/** D-70: tetti per valuta (999.999,99 con centesimi, 99.999.999 senza); D-69: conversione nella valuta del viaggio. */
public final class AmountRules {
    public static final String TOO_MUCH_CENTS = "Al massimo 999.999,99 (due decimali)";
    public static final String TOO_MUCH_NO_CENTS = "Al massimo 99.999.999 (senza decimali)";

    private AmountRules() {}

    public static void check(String field, BigDecimal amount, String currency) {
        int digits = Currencies.fractionDigits(currency);
        if (amount.stripTrailingZeros().scale() > digits) {
            throw new FieldException(field, digits == 0
                    ? article(Currencies.name(currency)) + Currencies.name(currency) + " non ha centesimi" : TOO_MUCH_CENTS);
        }
        int maxInt = digits == 0 ? 8 : 6;
        if (amount.setScale(digits, RoundingMode.HALF_UP).precision() - digits > maxInt) {
            throw new FieldException(field, digits == 0 ? TOO_MUCH_NO_CENTS : TOO_MUCH_CENTS);
        }
    }

    public static BigDecimal convert(BigDecimal amount, BigDecimal fxRate) {
        return amount.multiply(fxRate).setScale(2, RoundingMode.HALF_UP);
    }

    /** «Lo yen giapponese», «Il fiorino ungherese», «La corona islandese», «Il won sudcoreano»: l'articolo dal nome italiano. */
    private static String article(String name) {
        String first = name.split(" ")[0];
        if (first.startsWith("yen") || first.startsWith("zloty")) return "Lo ";
        if (first.endsWith("a")) return "La ";
        return "Il ";
    }
}
```

Nota: `precision() - digits` per un numero con `setScale(digits)` conta le cifre intere (per 0,50 → precision 2, digits 2 → 0 cifre intere: va bene, è sotto il tetto). Verifica con il test: 999999.99 → precision 8 − 2 = 6 ≤ 6 ok; 1000000.00 → 9 − 2 = 7 > 6 → errore.

```ts
/** D-70: valute senza centesimi, lo stesso elenco di BE/.../common/Currencies.java (Intl dà già 0 decimali a JPY e HUF, Java no a HUF). */
export const NO_CENTS: ReadonlySet<string> = new Set(['JPY', 'HUF', 'ISK', 'KRW'])
export const fractionDigits = (currency: string): 0 | 2 => (NO_CENTS.has(currency) ? 0 : 2)
/** Tetto in centesimi: 999.999,99 con centesimi, 99.999.999 senza. */
export const maxCents = (currency: string) => (fractionDigits(currency) === 0 ? 9_999_999_900 : 99_999_999)
/** «yen», «fiorino ungherese» in minuscolo, per i messaggi («Lo yen non ha centesimi»). */
export function noCentsMessage(currency: string): string {
  const name = (names.of(currency) ?? currency).toLowerCase()
  const short = name.split(' ')[0]
  const article = /^(yen|zloty)/.test(short) ? 'Lo' : /a$/.test(short) ? 'La' : 'Il'
  return `${article} ${short} non ha centesimi`
}
```

```ts
import { useQuery } from '@tanstack/react-query'
import { ApiError } from '../../shared/api/client'
import { ratesApi } from '../../shared/api/ratesApi'

/** Il cambio di un giorno passato non cambia: resta in memoria; 404 e 503 non si ritentano (si scrive a mano). */
export function useRate(from: string, to: string, date: string, enabled: boolean) {
  return useQuery({
    queryKey: ['rates', date, from, to],
    queryFn: () => ratesApi.rate(from, to, date),
    enabled: enabled && from !== to && /^\d{4}-\d{2}-\d{2}$/.test(date),
    staleTime: Infinity,
    retry: (count, error) => !(error instanceof ApiError && (error.status === 404 || error.status === 503)) && count < 1,
  })
}

/** «1 € = 177,82 JPY» → fxRate 0.00562366 (quanto vale 1 JPY in €), 8 decimali. */
export function toFxRate(perUnit: string): number {
  const n = Number(perUnit.replace(/\./g, '').replace(',', '.'))
  if (!Number.isFinite(n) || n <= 0) return 0
  return Number((1 / n).toFixed(8))
}

/** fxRate → «177,82»: quanti `from` vale 1 unità della valuta del viaggio, al massimo 4 decimali, senza zeri finali. */
export function fromFxRate(fxRate: number): string {
  if (!(fxRate > 0)) return ''
  return String(Number((1 / fxRate).toFixed(4))).replace('.', ',')
}
```
