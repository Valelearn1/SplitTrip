# v3.3 «Inclusiva» — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SplitTrip verificata WCAG 2.2 AA (axe nei test di ogni pagina + verifica a mano registrata), testi senza genere protetti da test, adattamento a testo grande / contrasto aumentato / colori forzati, e i 22 ritocchi rimandati.

**Architecture:** un helper `expectAccessible()` con `axe-core` gira dentro i test di pagina esistenti; un test per lato (FE e BE) scansiona il codice senza commenti e blocca le forme con genere; un blocco di regole in `index.css` reagisce alle media query di sistema; i ritocchi sono piccole correzioni ciascuna con il proprio test.

**Tech Stack:** React 19 + TypeScript + Vite 8, Vitest + Testing Library + MSW, `axe-core` 4.14 (solo test); Spring Boot 4.1 / Java 25, JUnit 5, MockMvc, Testcontainers.

**Spec:** `docs/superpowers/specs/2026-10-19-v3.3-inclusiva-design.md`

## Global Constraints

- WCAG 2.2 livello AA; nessuna dipendenza nuova in produzione (axe solo `devDependencies`).
- Linguaggio per riformulazione: niente asterischi, schwa o doppie forme; «nessuno»/«ognuno» restano se nulla si accorda.
- Nomi nel codice invariati (`ORGANIZER`, `isOrganizer`, codici dei badge).
- Soldi e API invariati (stesse rotte e forme JSON); cambiano solo testi dei messaggi.
- Regole di progetto (CLAUDE.md): colori dai token; mai solo colore; 44 px; Problem Details; TDD; i commit li fa l'autrice («Puoi committare: `<messaggio>`» + Stage All, mai `git commit`).
- Comandi: FE da `FE/` (`npm test -- --run`, `npx tsc -b`, `npx eslint src`, `npm run build`); BE da `BE/` (`sh mvnw test`, serve Docker).

## Review Focus

1. Un testo riformulato che rompe un test o una frase: ogni stringa cambiata ha il suo test aggiornato prima (Task 2–3), e il test di linguaggio non deve dare falsi allarmi su URL o identificatori inglesi (`isOrganizer`). Test nel Task 2 («gli URL non contano come commento»).
2. Testo grande al 200% su iPhone: la base segue Dynamic Type **solo su iOS** (sul Mac `-apple-system-body` vale 13 px e rimpicciolirebbe tutto). Test nel Task 4 (la regola è dentro `@supports (... ) and (-webkit-touch-callout: none)`).
3. Contrasto aumentato nel tema scuro: le variabili ridefinite valgono anche sotto `:root[data-theme='dark']`. Test nel Task 4.
4. Percentuali delle categorie del riepilogo che sommano sempre 100 (anche 3 categorie uguali). Test nel Task 6.
5. Il token di ripristino che lascia la barra degli indirizzi non deve rendere il link «non valido» (il token resta in memoria). Test nel Task 7.

**Note rispetto alla spec (decise scrivendo il piano):**
- Solo `axe-core`, senza `vitest-axe`: il pacchetto è fermo alla 0.1.0 (2022) e aggiunge solo un matcher; l'helper fa lo stesso in 10 righe.
- I controlli axe si aggiungono ai test di pagina esistenti; per le 3 pagine senza test (Registrazione, Foto, Cestino) si crea un test minimo; Password dimenticata e Nuova password sono già in `PasswordReset.test.tsx`.
- La verifica a mano (Task 8) viene dopo le correzioni dei Task 1–7, così il registro descrive l'app finale.

import axe from 'axe-core'
import { expect } from 'vitest'

/** WCAG 2.2 A/AA con axe (D-65). Il contrasto lo verifica già il test sui token: jsdom non impagina. */
export async function expectAccessible(root: Element = document.body) {
  const results = await axe.run(root, {
    runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa'] },
    rules: { 'color-contrast': { enabled: false } },
  })
  const found = results.violations.map((v) => `${v.id}: ${v.help} → ${v.nodes.map((n) => n.target.join(' ')).join(' | ')}`)
  expect(found).toEqual([])
}
```

    /** Percentuali intere che sommano 100 (resto maggiore, come le quote): a parità vince l'ordine. */
    static List<Integer> percentages(List<BigDecimal> amounts, BigDecimal total) {
        if (total.signum() == 0) return amounts.stream().map(a -> 0).toList();
        List<BigDecimal> exact = amounts.stream().map(a -> a.multiply(BigDecimal.valueOf(100)).divide(total, 6, RoundingMode.DOWN)).toList();
        int[] floor = exact.stream().mapToInt(BigDecimal::intValue).toArray();
        int missing = 100 - java.util.Arrays.stream(floor).sum();
        List<Integer> order = java.util.stream.IntStream.range(0, exact.size()).boxed()
                .sorted((i, j) -> exact.get(j).remainder(BigDecimal.ONE).compareTo(exact.get(i).remainder(BigDecimal.ONE))).toList();
        for (int k = 0; k < missing && k < order.size(); k++) floor[order.get(k)]++;
        return java.util.Arrays.stream(floor).boxed().toList();
    }
```
